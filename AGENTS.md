# AGENTS.md — Blocknet node

Bitcoin Core fork implementing the Blocknet Protocol (PoS staking, XBridge atomic-swap DEX, XRouter, Service Nodes). Version lives in `configure.ac` (`CLIENT_VERSION_*`).

## Naming trap

All binaries are renamed: `blocknetd`, `blocknet-cli`, `blocknet-tx`, `blocknet-wallet`, `blocknet-qt` (in `src/`). Docs, comments, and test names still say `bitcoin-*`. The unit-test binary is `src/test/test_blocknet` (sources keep `test_bitcoin*.cpp` names). Functional tests default to `src/blocknetd` / `src/blocknet-cli` (overridable via `BITCOIND` / `BITCOINCLI` env vars).

## Build (order matters)

```bash
make -C depends HOST=x86_64-pc-linux-gnu -j$(nproc)   # or your HOST triplet
./autogen.sh
CONFIG_SITE=$PWD/depends/x86_64-pc-linux-gnu/share/config.site ./configure --prefix=/ --with-gui=qt5
make -j$(nproc)
```

- Use `depends` for all libs (Boost, OpenSSL 3, Qt 5.15.14, BDB 4.8, libevent); do not mix system libs. The `CONFIG_SITE` file wires all `--with-*` paths automatically.
- System BDB is >= 5.1 and breaks wallet compat; either use depends BDB 4.8 or pass `--with-incompatible-bdb`.
- C++17 required (OpenSSL 3, libc++-friendly code).
- Only 64-bit hosts are supported: `x86_64-linux-gnu`, `aarch64-linux-gnu`, `x86_64-w64-mingw32`, `aarch64-w64-mingw32`, `x86_64-apple-darwin`, `arm64-apple-darwin`.
- The tree contains an in-tree build (generated `Makefile`, `configure`, `*.o`, `*.a`, binaries, `guix-build-*/`); all gitignored — don't commit or hand-delete them.
- `--with-gui=qt5` is the release policy: Guix builds hard-fail if `blocknet-qt` is missing (daemon-only artifacts are never shipped).

## Tests

- Unit tests: `make check` → runs `src/test/test_blocknet`. Blocknet-specific suites: `servicenode_tests`, `xbridge_tests`, `xrouter_tests`, `governance_tests` (in `src/test/`).
- Single suite: `src/test/test_blocknet --run_test=servicenode_tests` (add `--log_level=all` for verbosity).
- Functional tests (Python, run built binaries): `test/functional/test_runner.py <name>.py` for one test, no args for the full suite. Requires a prior build **and** `test/config.ini` — that file is generated by `./configure`; without it the runner aborts.
- Functional tests are all inherited Bitcoin Core tests; there are no functional tests for xbridge/xrouter/servicenode — Blocknet logic is covered only by the unit suites above.
- The ZMQ functional test (`interface_zmq.py`) needs `python3-zmq`.

## Lint

`test/lint/lint-all.sh` runs all `test/lint/lint-*.sh` checks (whitespace, includes, locale, python...). CI itself only runs shellcheck/yamllint on workflows/scripts.

## Deterministic builds (Guix) and release

- Local deterministic build, no host Guix needed (uses Docker image `blocknet-guix:22.04`, built from `contrib/guix/Dockerfile`):
  ```bash
  ./contrib/guix/docker-run.sh "x86_64-linux-gnu"
  # or: HOSTS="x86_64-linux-gnu aarch64-linux-gnu" ./contrib/guix/docker-run.sh
  ```
  Artifacts land in `blocknet-binaries/<host>/`.
- macOS darwin hosts require the pinned Apple SDK: source `contrib/guix/macos-sdk.env`, fetch+extract into `depends/SDKs/` (commands are in that file's header comment). Without an SDK, darwin hosts are soft-skipped with a warning.
- Windows builds use a pinned llvm-mingw (Clang/UCRT/libc++) toolchain for both x86_64 and aarch64 — no GCC mingw path exists. Consequence: **include what you use**; libc++ does not provide libstdc++'s transitive includes (`<iterator>`, `<algorithm>`, `<new>`, ...).
- Release: pushing a tag `v*` triggers `.github/workflows/release.yml` (Guix all-hosts build → SHA256SUMS → Docker Hub image → GitHub release). CI runs on `master`, `dev`, and `feat/*`/`fix/*` branches.

## Workflow map

- `.github/workflows/ci.yml` — canonical CI (Guix 6-host matrix + native-sanity container build + lint).
- `.github/workflows/release.yml` — canonical release flow.
- `.github/workflows/build.yml` and `publish.yml` — **deprecated no-op shims**; ignore them.
- Gitian was fully removed from this tree (`contrib/gitian-keys/` was deleted with the modernization pass); don't reintroduce it.
- `master` = stable (tracks latest release); `dev` = development branch.
- Prior session plans live in `.opencode/plans/` — check there before redoing in-flight build/release work.
